# SrunKeeper

SRun（深澜）校园网批量认证与自动重连工具，支持纯命令行运行和本地网页控制台。

认证服务器默认使用杭州电子科技大学的认证地址。其他使用兼容 SRun 协议的学校可以调整学校配置；如果接口、认证算法或响应格式不同，需要进一步适配，不能保证仅修改地址即可通用。

## 功能

- 支持多个账号、多个设备，同一账号可关联多台设备。
- 定时检测设备在线状态，已在线则跳过，离线后自动认证。
- 单台设备检测或认证失败，不影响其他设备。
- 支持命令行持续运行、单次检测和网页控制台。
- 网页左侧设置账号、设备、学校和检测间隔，右侧启动、停止服务并查看设备日志。
- 账号与设备独立保存，设备通过下拉框选择关联账号。
- 按设备分组展示日志，自动刷新时保留滚动位置。
- 像素风界面，页面、字体和 Logo 随程序内嵌，断网也可打开。
- 学校、用户、系统配置分别保存为独立 JSON 文件。

## 快速开始

### 下载运行

从仓库的 **Releases** 页面下载 Windows x64 压缩包，完整解压后运行。用户无需安装 Go、Node.js 或 WebView2。

```text
SrunKeeper-<版本>-windows-amd64/
├── SrunKeeper.exe
├── 启动网页界面.cmd
├── 启动命令行.cmd
├── README.md
└── config/
    ├── school.json
    ├── user.json
    └── system.json
```

推荐首次使用时双击 **`启动网页界面.cmd`**：

1. 确认电脑已连接校园网。
2. 浏览器自动打开 `SrunKeeper - 控制台`。
3. 在左侧添加账号和密码，点击 **保存账号**。
4. 添加设备，填写 IP、描述，从下拉框中选择账号，点击 **保存设备**。
5. 确认学校配置和检测间隔，修改后点击 **保存学校与系统设置**。
6. 在右侧点击 **启动服务**，查看各设备的认证状态和日志。

三个保存按钮只提交各自区域的内容，其他区域的未保存草稿会保留。已有账号的密码留空表示保留原密码；账号改名后需要重新填写密码。删除已被设备引用的账号前，须先修改或删除对应设备并保存。

网页模式初始处于停止状态。点击 **停止服务** 会停止检测和自动重连，但保留网页和日志。停止服务不会主动注销校园网账号。

关闭浏览器不会停止已启动的服务。在启动终端中按 `Ctrl+C` 可退出程序，关闭该终端也会结束程序。

配置完成后，也可以双击 **`启动命令行.cmd`**，使用同一份配置直接开始检测。

### 命令行运行

在解压后的目录打开 PowerShell：

```powershell
# 持续检测，自动重连
.\SrunKeeper.exe

# 打开网页控制台，在页面中手动启动服务
.\SrunKeeper.exe -web

# 只检查并认证一轮
.\SrunKeeper.exe -once

# 指定配置目录
.\SrunKeeper.exe -config D:\MyConfig

# 初始化缺失的配置文件，不覆盖已有文件
.\SrunKeeper.exe -init

# 网页模式不自动打开浏览器，手动访问终端显示的完整地址
.\SrunKeeper.exe -web -no-browser

# 查看版本
.\SrunKeeper.exe -version
```

默认配置目录为 **可执行文件旁的 `config`**，不受终端当前目录影响。网页服务只监听 `127.0.0.1`，端口自动分配。重新启动程序后，请使用终端显示的新地址。

`-once` 模式下，只要有设备未确认在线，程序退出码为 `1`；所有设备确认在线时为 `0`。`-once` 与 `-web` 不能同时使用。

## 配置说明

### 学校层：`config/school.json`

```json
{
  "description": "杭州电子科技大学",
  "host": "http://192.168.112.30",
  "ac_id": "0",
  "n": "200",
  "type": "1",
  "enc_ver": "srun_bx1"
}
```

| 参数 | 说明 |
| --- | --- |
| `description` | 学校名称或备注，可留空，不参与认证 |
| `host` | 认证服务器根地址，不填写具体接口路径 |
| `ac_id` | 接入标识，以学校认证配置为准 |
| `n`、`type` | 认证协议参数，默认沿用参考实现 |
| `enc_ver` | 编码版本，目前仅支持 `srun_bx1` |

HTTP 默认使用 80 端口，HTTPS 默认使用 443 端口。如学校使用其他端口，可以写成 `http://认证服务器地址:端口`。

### 用户层：`config/user.json`

发布时使用空配置，不包含账号、密码或设备信息：

```json
{
  "account": {},
  "device": []
}
```

填写示例：

```json
{
  "account": {
    "账号A": "密码A",
    "账号B": "密码B"
  },
  "device": [
    {
      "ip": "192.168.1.2",
      "description": "电脑",
      "account": "账号A"
    },
    {
      "ip": "192.168.1.3",
      "description": "手机",
      "account": "账号B"
    }
  ]
}
```

`account` 保存账号与密码的对应关系。每个设备必须填写有效且不重复的 IP、非空描述，以及存在于 `account` 中的账号。设备 IP 由用户手动填写，应使用校园网认证时对应的 IP。

密码保存在本机 JSON 文件中，网页读取配置时不回传已保存的密码。`config/user.json` 已被 Git 忽略，仓库提供 `config/user.json.example` 作为空配置示例。

### 系统层：`config/system.json`

```json
{
  "check_interval_seconds": 60
}
```

`check_interval_seconds` 为全局检测间隔，单位为秒，范围为 `1–86400`，默认 `60`。所有设备都参与自动重连，没有设备级开关。

设备按顺序处理，每次认证服务器请求最多等待 10 秒。每轮完成后等待配置的间隔，再开始下一轮；因此两轮开始时间之间还包含上一轮的处理耗时。

通过网页保存后立即应用。直接修改配置文件后，需要重新启动程序。
